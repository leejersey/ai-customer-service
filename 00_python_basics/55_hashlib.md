# hashlib：同一个词每次都落到同一格

阶段 5 的假向量没有模型。它要做的是：二字词「退款」每次都进向量的同一格，下次还是那一格。`hashlib` 把一段文字稳定地变成一个整数。这里用它选格子，不是用它保护密码。

阶段 5 用在 [嵌入](../stage5_vector_memory/docs/02_embedder.md) 的 `_bucket`。二字词怎么切，阶段 4 已经做过，这一课只讲「切完之后放进哪一格」。

## 先用一句人话

`md5` 吃字节，吐出一串十六进制。`int(那串字, 16)` 把它变成整数。再 `% 维度`，就得到 0 到「维度减 1」之间的格子号。同一段字，格子号不变。

## 打个比方

传达室把每张纸条变成一个固定的抽屉号。同样的纸条永远进同一个抽屉。这不是加密保险柜。md5 用来防别人伪造已经过时了，我们也不拿它保存密钥。它只是一个不会摇骰子的抽屉分配员。

## 自己动手

```python
import hashlib

digest = hashlib.md5("退款".encode("utf-8")).hexdigest()
print(digest)
number = int(digest, 16)
print(number % 8)
print(number % 8)
```

预期：

```text
44c198c146aecc3f2ac5c5c7017587f9
1
1
```

`.encode("utf-8")` 把字符串变成字节。哈希吃的是字节，不直接吃「字」。

`hexdigest()` 是十六进制文本。`int(文本, 16)` 按十六进制读成整数。第二个参数 `16` 是进制，不是「只取 16 位」。

`% 8` 是余数，结果只会是 0 到 7。维度是 256 时就写 `% 256`。再运行一次，余数仍是 `1`。假向量靠的就是这种稳定，而不是随机。

「退款」和「退钱」的十六进制不同，余数通常也不同，所以它们进不同的格子，余弦是 0。真模型才会把这两种说法放近。

## 常见错误

忘了 `.encode(...)`。`hashlib.md5` 不接受普通字符串，会报：

```text
TypeError: Strings must be encoded before hashing
```

把 md5 当成密码的保存方法。这一课的整数谁都能再算一遍，不能用来藏密钥。密钥仍放在 `.env`，见 [环境变量](20_env.md)。

以为哈希会看「意思」。它只看这一串字节。改一个字，抽屉号通常就变了。

## 练习

1. 同一段文字，`% 8` 跑两次，结果会变吗？
2. `int(digest, 16)` 里的 `16` 是什么？
3. 为什么假向量对不上「退钱」和「退款」？

## 答案

1. 不会。同样的字节每次都变成同一个整数。
2. 按十六进制把那串字读成整数。
3. 两个词的字节不同，格子不同。假向量没有「意思相近」这一步。
