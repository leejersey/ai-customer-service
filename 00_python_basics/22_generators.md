# 生成器：一次给你一个，而不是先装成一整叠

流式脚本里有：

```python
for chunk in stream:
```

这里的 `stream` 不是已经装好的列表。它是「你每要下一项，才去拿下一项」的东西。生成器就是自己写这种东西的一种办法。

## 先用一句人话

列表是菜已经全部上桌。生成器是厨房做一个、你吃一个。你不喊下一道，厨房可以还没做它。因此你不能在开始时问「一共几道」，因为厨房自己也可能还没决定。

## 打个比方

`yield` 是把一道菜递出窗口，然后厨师站着等你吃完并再要。他不是把今晚所有的菜先堆在窗口。

## 自己动手

```python
def count_slowly():
    print("准备交出一")
    yield "一"
    print("准备交出二")
    yield "二"

for piece in count_slowly():
    print("拿到", piece)
```

预期：

```text
准备交出一
拿到 一
准备交出二
拿到 二
```

如果 `yield` 是普通的 `return` 加列表，你会先看到两句「准备」，再看到两个「拿到」。顺序交错，说明函数在每次交出之后暂停了。

`for` 的语法和列表课里完全一样。变的是右边那个东西什么时候准备好下一项。

流式接口的 `stream` 由 SDK 提供，不一定是我们写的 `yield`，但用法相同：循环的每一轮都可能在等网络。所以失败可以发生在已经打印出半句话之后。`try` 必须包住整个 `for`，不能只包住创造出 `stream` 的那一行。

## 和「拼全文」的关系

生成器不负责把碎片收成一篇文章。你要自己收：

```python
pieces = []
for piece in ["请准备", "订单号"]:
    pieces.append(piece)
print("".join(pieces))
```

预期：

```text
请准备订单号
```

`"".join(pieces)` 用空字符串把列表粘起来，中间不加额外符号。流式脚本里的 `pieces` 就是这个笔记本。屏幕上的 `print` 是另一件事，不会自动写进笔记本。

## 常见错误

对生成器先 `len(stream)`。很多流不支持问长度，你会得到：

```text
TypeError: object of type 'generator' has no len()
```

或者流对象给出别的 `TypeError`。不要问长度。用循环数自己见到了几个非空片段。

把生成器当成列表用两次：

```python
def one():
    yield "只有一次"

seq = one()
print(list(seq))
print(list(seq))
```

预期：

```text
['只有一次']
[]
```

第二次是空的。值已经被取走过，生成器不会倒回去。流式响应同样不能「再 for 一遍就再得到同一段回复」。要保留，就在第一次循环里放进 `pieces`。

`list(seq)` 会把剩余的项全部取出来变成列表。对流式来说，这等于一直等到结束，屏幕上就失去了「边到边显示」。学习生成器时可以用 `list` 看清内容，正式的流式循环不要一开始就 `list(stream)`。

## 练习

1. 写一个生成器，依次 `yield` `"你"` 和 `"好"`。用 `for` 打印。预期两行是什么？「准备」这种提示不要写，只交出这两个字。
2. 为什么流式循环中途断网，前面的字可能已经出现在屏幕上？
3. 只 `print` 每个片段、不 `append`，下一轮对话为什么会失忆？

## 答案

1. 两行：`你` 然后 `好`。
2. 因为前面的片段在失败之前已经被循环拿到并打印了。生成器不是等全部成功才给你第一项。
3. 屏幕不是 `messages`。下一轮发送的是列表。列表里没有这条 `assistant`，模型就看不见刚刚那些字。
