# input：停下来等你打一行

`04_cli_chatbot.py` 里：

```python
user_text = input("你：").strip()
```

## 先用一句人话

`input` 把括号里的提示显示出来，然后停住，直到你打完一行并按回车。它交回来的是你打的那一行文字，不含最后那个回车。

## 打个比方

柜台把麦克风推过来。在你说话之前，后面的「发给模型」不会发生。你说的话是一段字符串，哪怕你打的是 `123`，拿到的也是文字 `"123"`，不是数字 `123`。

## 自己动手

把下面存成临时文件再运行。不要只在脑子里想，因为 `input` 的重点是程序会停住。

```python
name = input("名字：")
print("你输入的是")
print(name)
```

运行后先看到 `名字：`，并且没有回到终端提示符。输入 `小星` 再回车。预期：

```text
名字：小星
你输入的是
小星
```

`名字：小星` 这一行里，`名字：` 是提示，`小星` 是你打的字，它们连在同一行是终端的显示方式。

`.strip()` 去掉首尾空白：

```python
text = "  退出  "
print(text.strip())
```

预期：

```text
退出
```

所以你不小心打成 `退出 `（末尾有空格）时，仍然能对上退出命令。不去掉的话，集合里没有带空格的那一项，这句话会被当成顾客的问题发送出去。

`strip` 不动中间的空格。`"我想 退货".strip()` 仍然是 `我想 退货`。

## 没有下一行的时候

你按 Ctrl+D（macOS / Linux）或 Ctrl+Z 再回车（Windows），表示「输入到此结束」。`input` 会失败，错误名叫 `EOFError`。客服脚本接住它，当成正常告别。

如果一个文件被重定向给脚本当输入，文件读完也会是 `EOFError`。那不是网络故障。

`input` 永远给你字符串。想要数字就要 `int(...)`，并准备好别人输入了「十二」时的 `ValueError`。本阶段的客服不需要把输入转成数字。

## 常见错误

在交互模式里调用 `input`，提示符和 `>>>` 叠在一起，你以为程序死了。其实它在等。先打一行再回车。

写成 `input() = "你好"`。左边不是盒子。应该是 `text = input()`。

以为 `input` 能一次读入很多行直到你输入空行。它只读到下一个回车。下一句要等下一次循环再调用 `input`。

## 练习

1. `input` 交回来的 `123` 是整数还是字符串？
2. 为什么退出判断要放在 `strip()` 之后？
3. 管道把输入用完之后出现的 `EOFError`，应该当成接口 401 那样的失败吗？

## 答案

1. 字符串 `"123"`。
2. 否则首尾多打的空格会让 `"退出"` 对不上集合里的 `"退出"`，口令失效，还可能把口令发给模型。
3. 不应该。那是「没有更多输入了」，脚本把它当成告别。401 是密钥被拒绝，是另一类失败。
