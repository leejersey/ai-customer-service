# `if __name__ == "__main__"`：这个文件是被运行，还是被导入

四个脚本的末尾都有：

```python
if __name__ == "__main__":
    try:
        main()
    except KeyboardInterrupt:
        print("\n已手动中断。")
```

## 先用一句人话

Python 会给每个正在加载的文件一个名字，放在 `__name__` 里。如果你是用 `python 这个文件.py` 直接运行它，这个名字就是 `"__main__"`。如果它是被别人 `import` 的，名字就是文件自己的模块名，比如 `"config"`。

这句 `if` 的意思是：只有「我就是今天被直接运行的那张菜谱」时，才开始做 `main()`。

## 打个比方

一张调料表可以被别的菜谱引用。被引用时，它只负责把盐的做法登记好，不应该立刻把整桌菜做出来。只有顾客点名「今天就做这张」时，才真正开做。

`config.py` 没有这句调用，是因为它永远只被引用，不应该自己去请求模型。四个示例脚本有这句，是因为它们就是你要点名运行的入口。

## 自己动手

写 `demo_name.py`：

```python
print("加载时名字是", __name__)

def greet():
    print("函数被调用")

if __name__ == "__main__":
    greet()
```

直接运行：

```bash
python demo_name.py
```

预期：

```text
加载时名字是 __main__
函数被调用
```

再打开交互模式，先 `cd` 到这个文件所在的目录，或者把该目录留在查找路径里，然后：

```python
import demo_name
```

预期只有：

```text
加载时名字是 demo_name
```

没有「函数被调用」。`import` 仍然执行了文件顶层的 `print`，但 `if` 条件不成立，`greet()` 没有发生。

做完可以删掉 `demo_name.py`。不要把它命名成和标准库冲突的名字。

## 为什么付费代码必须放在这道门后面

`main()` 里面会调用模型，可能花钱。如果没有这道门，将来某个文件写了 `import` 你的脚本，导入的瞬间就会发出请求。你以为只是借用一个函数，账单已经记上了。

顶层的 `TEMPERATURE = 0.7` 仍然会在导入时执行。那只是赋值，不联网。贵的步骤放在函数里，再由这道门决定要不要调用。

两个下划线包住的名字，是 Python 自己使用的名字。你不要给自己的变量起 `__main__` 或 `__name__`。

## 常见错误

写成 `if __name__ == "__main__":` 但 `main()` 缩进到了 `if` 外面。那 `main()` 就每次加载都执行，这道门形同虚设。看行首是不是在 `if` 里面。

拼成 `__main__` 少了一个下划线，或写成 `"main"`。条件永远不成立，你运行文件却什么都不发生，也没有报错。因为这只是一个没走进去的 `if`。

以为这行是 Python 规定的「文件必须有的魔法，否则不能运行」。不是。没有它，文件照样从上到下运行。它是我们加上的开关。

## 练习

1. 直接运行一个文件时，`__name__` 的值是什么？
2. `import config` 时，`config.py` 里的 `__name__` 会是 `"__main__"` 吗？
3. 把 `client.chat.completions.create(...)` 挪到文件最顶层、不放进任何函数，会有什么实际风险？

## 答案

1. 字符串 `"__main__"`。
2. 不会。它会是 `"config"`。所以 `config.py` 即使复制了这道门，被导入时也不会走进去。
3. 任何一个导入这个文件的人，都会在导入时立刻发起一次可能花钱的网络请求，而且导入方还没准备好要问的问题。
