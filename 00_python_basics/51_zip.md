# zip：两排对齐着一起拿

[for](14_for.md) 一次走一叠。阶段 4 要同时走两叠：这一字和它右边的字，配成一个二字词。三份等长的列表也可以一起走。

阶段 4 用在 [检索](../stage4_rag/docs/03_retrieve.md) 的 `zip(chars, chars[1:])`，以及建好索引之后同时取出「段、向量、次数」。右边那一排少掉第一个字，用的是 [切片](39_slice.md)。

## 先用一句人话

`zip` 把多排的第 0 项捆在一起，再把第 1 项捆在一起。哪一排先用完，它就停。多出来的项不会单独出现。

## 打个比方

两列队伍并排向前。每一拍，左右各走出一个人，配成一对。较短的那一列走完，长的那列剩下的人留在原地，不再配对。

## 自己动手

```python
chars = ["退", "货", "政", "策"]
for left, right in zip(chars, chars[1:]):
    print(left + right)
```

预期：

```text
退货
货政
政策
```

`chars[1:]` 是从第 2 个字开始的新列表：`货 政 策`。和原列表对齐后，就是 (退, 货)、(货, 政)、(政, 策)。原列表多出来的最后一次没有伙伴，`zip` 停在较短的那排。

较短的一边会把长的一边截掉：

```python
print(list(zip(["甲", "乙"], ["1"])))
```

预期：

```text
[('甲', '1')]
```

`"乙"` 没有配对，被留下了。阶段 4 只有在三份列表等长时才把它们 `zip` 在一起，就是为了不要悄悄丢掉某一段。

`for left, right in zip(...)` 是一次接住两样东西。三份列表就接住三个名字。

## 常见错误

以为 `zip` 会把短的那一排用空字符串补齐。它不会。短的结束，循环结束。

写成 `zip(chars)` 只放一排。每一对里只有一个元素，拆不成 `left, right`，会 `ValueError`。

配二字词时忘了切片，写成 `zip(chars, chars)`。每个字会和自己配对，得到「退退」「货货」，那不是相邻的两个字。

## 练习

1. `list(zip(["a", "b"], ["1", "2", "3"]))` 有几对？`"3"` 还在吗？
2. `chars[1:]` 比 `chars` 少了哪一个字？
3. 为什么二字词要用 `zip(chars, chars[1:])`，而不是 `zip(chars, chars)`？

## 答案

1. 两对。`"3"` 不在结果里，因为左边已经用完。
2. 少了第一个字。
3. 自己和自己配对，得到的是同一个字写两遍。错开一位，才是相邻的两个字。
