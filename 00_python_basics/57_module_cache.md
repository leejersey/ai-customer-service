# 模块级缓存：贵的东西只准备一次

[导入](08_import.md) 说过，模块在一次进程里会被加载一遍。加载之后，模块顶上的变量还在。阶段 5 的中文嵌入模型很大，不能每问一句就重新进内存一次。

阶段 5 用在 [嵌入](../stage5_vector_memory/docs/02_embedder.md) 的 `_BACKEND` 和 `_MODEL`。函数里要给这种变量重新赋值，必须写 `global`。

## 先用一句人话

把准备好的对象放在函数外面的名字上。下次再进函数，先看这个名字是不是已经有了。有了就直接用。

## 打个比方

店里的精密秤打开一次要很久。第一位顾客来时你打开它，放在柜台上。后面的顾客用柜台上这一台，而不是每人再开一台。柜台是模块本身，不是某一次函数调用里的临时桌子。

## 自己动手

```python
_cache = None

def get_model():
    global _cache
    if _cache is not None:
        print("已经有了，不再创建")
        return _cache
    print("第一次创建")
    _cache = {"name": "toy"}
    return _cache

print(get_model())
print(get_model())
```

预期：

```text
第一次创建
{'name': 'toy'}
已经有了，不再创建
{'name': 'toy'}
```

`global _cache` 是在说：接下来对 `_cache` 的赋值，写的是模块那一层，不是函数自己的临时名字。

去掉 `global` 再赋值，函数里会出现一个新的局部变量，外面的 `_cache` 仍是 `None`。下次进来还是「第一次」。这是这一课最常见的坑。

阶段 5 第一次调用 `embed_texts` 时决定用真模型还是假向量，记在 `_BACKEND`。同一进程里的第二句不会再下载。进程结束，这块内存就没了。长期记忆的向量在磁盘上，那是另一件事，见阶段 5 的记忆课。

## 常见错误

忘了 `global`，函数里 `_cache = ...`。屏幕上像是创建过，模块外面的名字却还是 `None`。每一问都重新加载模型，又慢又可能再次去联网。

在导入模块的那一瞬间就加载模型。还没问问题，程序就去下载。阶段 5 把加载放在第一次嵌入时，示例 1 只用假向量函数，就不会碰到下载。

把缓存当成「所有顾客共用的记忆」。缓存的是模型这台秤，不是某位顾客说过的话。顾客的事实在他自己的索引文件里。

## 练习

1. 为什么第二次调用不再打印「第一次创建」？
2. 去掉 `global` 之后，模块顶上的 `_cache` 会变成什么？
3. 模型缓存和阶段 5 写在 `data/memory/` 里的事实，哪一个会在进程退出后还在？

## 答案

1. `_cache` 已经不是 `None`，函数在创建之前就返回了。
2. 仍是 `None`。赋值只发生在函数内部的同名局部变量上。
3. 磁盘上的 `index.faiss` 和 `meta.json` 还在。内存里的模型缓存随进程结束消失。
