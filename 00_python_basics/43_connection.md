# 连接对象：手里的是把手，不是数据

阶段 2 的 SQLite 连接、阶段 3 的 Redis 客户端，都是同一种东西：你拿着一个对象，调用它的方法，事情发生在这条连接的另一头。另一头可能是一个文件，也可能是另一个进程。

`with` 怎样在离开时自动收尾，已经在 [第 34 课](34_with.md)。这一课不再写 `__enter__`。要分清的是：连接对象不是订单号，也不是那一串消息。

阶段 3 用在 [Redis 入门](../stage3_memory/docs/04_redis.md) 的 `client`。下面的例子只用标准库能表达的形状，不需要先安装 Redis。

## 先用一句人话

连接对象是通向一份存储的把手。`set` / `get` 通过这只把手读写。`close` 放下把手。把手放下之后，若数据本来就在另一个还活着的服务里，数据还在；若数据只放在这只把手里面，把手一丢，数据就没了。

## 打个比方

对讲机是把手，仓库在马路对面。你按对讲机说「记下 10086」。关掉对讲机，仓库里的记录还在，只是这只对讲机不能再喊话。若你从来没有马路对面的仓库，只是在对讲机壳子里夹了一张纸，丢掉对讲机，纸也没了。fakeredis 和本阶段的内存实现属于后一种，用来让练习跑完。真正的 Redis 是前一种。

有人把「接下来这些命令都从这条连接出去」叫做这条连接的上下文。那是在说命令的去向，不是说 Python 的 `with`。`with` 只负责离开时调用关闭。

## 自己动手

```python
class ToyStore:
    def __init__(self):
        self._open = True
        self._data = {}

    def set(self, key, value):
        if not self._open:
            raise RuntimeError("连接已经关上")
        self._data[key] = value

    def get(self, key):
        if not self._open:
            raise RuntimeError("连接已经关上")
        return self._data.get(key)

    def close(self):
        self._open = False

store = ToyStore()
store.set("order_id", "10086")
print(store.get("order_id"))
store.close()
print("把手已放下")
```

预期：

```text
10086
把手已放下
```

关上之后再 `get`，会失败。这是把手不能用了，不是订单号这个概念消失了。玩具把数据放在对象内部，所以这个例子里关上之后你也拿不到那个字典了，除非在 `close` 之前自己抄出来。

阶段 3 的 Redis 客户端同样有 `set`、`get`、`close`。差别是数据在另一个进程里时，`close` 只结束这一次连接，键还在，直到过期或被删除。连不上对面时，`ping` 会失败，练习改用一个方法名相同的替身。替身仍然是一只把手，只是仓库不在进程外面。

不要把这只把手放进要 `json.dumps` 的字典。JSON 记不住对讲机。该存的是 `"10086"` 这种值。

## 常见错误

连接失败却不看屏幕上的原因，以为订单号没保存是 `set` 写错了。阶段 3 会先 `ping`。失败时打印「连接被拒绝」或「没有安装 redis」，然后改用替身，并说明退出后记不住。

在 `close` 之后继续 `get`。你会得到运行错误。命令行客服在循环结束时才 `close`，循环里面一直用同一只把手。

把「客户端对象还在」理解成「重启程序之后数据还在」。新的进程是一只新的把手。只有对面的 Redis 还开着，新把手才读得到旧键。内存里的替身随进程一起结束。

## 练习

1. 上面的例子里，`store.get("order_id")` 在 `close` 之前为什么能得到 `"10086"`？
2. `close` 之后，失败的原因是数据格式错了，还是把手已经不能用？
3. 为什么阶段 3 说 fakeredis 的方法名和 redis-py 一样，就可以不改后面的 `set` / `get`？

## 答案

1. `set` 把值放进了这只把手带着的字典，`get` 按同一个键取出来。
2. 把手已经不能用。`_open` 是假，方法拒绝继续工作。
3. 后面的代码只调用方法，不关心仓库在另一个进程还是在本进程。方法名和参数相同，调用的那几行就不用分叉。
