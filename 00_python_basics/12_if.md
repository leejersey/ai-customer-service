# if / else：按条件走不同的路

程序不是每行都做。`if` 先问一个是非题，是，就做缩进的那一块；否，就跳过那一块。`else` 是「上面那些都不是」时才做的一块。`elif` 是「再问一个新的是非题」。

`01_hello_llm.py` 里第一次分支是：

```python
if not response.choices:
    print("接口返回成功，但里面没有任何回复。可以重试一次。")
    raise SystemExit(1)
```

## 先用一句人话

`if` 像岔路。条件为真走岔进去的路，为假就走大路，大路是和 `if` 对齐的下一行。

## 打个比方

安检问「背包是空的吗」。是空的，就走「请你回头」那条通道（打印并结束）。不是空的，就继续去取包里的第 0 件东西。不先问空不空就伸手，空包会让你摔一跤（后面要学的 `IndexError`）。

## 是非题长什么样

```python
count = 0
if count == 0:
    print("是空的")
else:
    print("不是空的")
```

预期：

```text
是空的
```

两个等号 `==` 才是在问「相等吗」。一个等号是赋值。写错会出语法错误，或者悄悄把值改掉。

```python
if count = 0:
    print("错")
```

```text
SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?
```

后半句在不同 Python 版本上可能少几个词。前半句 `SyntaxError` 是一样的：一个等号不能用在 `if` 里面。

`not` 把是非题反过来。`not response.choices` 的意思是「choices 是空的」。空列表在这种是非题里会被当成「没有」。

比大小用 `<`、`>`。不等于用 `!=`。

同时满足用 `and`，满足一个就行用 `or`：

```python
text = ""
if text == "" or text == "退出":
    print("不要发给模型")
```

预期：

```text
不要发给模型
```

## elif 是按顺序问

```python
reason = "stop"
if reason == "length":
    print("被切断")
elif reason == "stop":
    print("自己说完")
else:
    print("别的原因")
```

预期：

```text
自己说完
```

问到第一个成立的就停，不会再问后面。所以具体的情况要写在笼统的情况前面。`config.py` 里先判断「是不是密钥错误」，再判断「是不是随便一种接口错误」，就是这个顺序。如果先问笼统的，后面的具体分支永远走不到。

## 常见错误

`if` 后面忘记冒号：

```text
SyntaxError: expected ':'
```

冒号写了，下一行却没有缩进，是[缩进课](10_indentation.md) 里的 `IndentationError`。

用 `if text == "退出" or "quit":`。这几乎总是走入分支。因为单独一个非空字符串 `"quit"` 在是非题里算成立，`or` 右边永远为真。要写成 `text == "退出" or text == "quit"`。我们后来改用集合和 `in`，就是为了少写这种重复。集合在列表课。

## 练习

1. `tokens = 10`。写出：大于 0 就打印 `有用量`，否则打印 `没有`。
2. 为什么密钥错误的 `if` 必须写在「任何一种接口错误」之前？
3. `if not pieces:` 在 `pieces = []` 时，会不会走进去？

## 答案

1. `if tokens > 0:` 下面 `print("有用量")`，然后和 `if` 对齐写 `else:`，下面 `print("没有")`。
2. 密钥错误也是接口错误的一种。先问笼统的那个，程序就进了笼统分支，不会再去打印「请重新粘贴密钥」。
3. 会。空列表在 `if not` 里算「没有东西」，条件成立。
