# 切片：从一排里取连续的一段

[列表课](13_lists_dicts.md) 会用 `papers[0]` 取一张，用 `papers[-1]` 取最后一张。阶段 3 要一次留下「最近几句」，不是只拿一张。方括号里写成 `开始:结束`，叫切片。

阶段 3 用在 [截断](../stage3_memory/docs/02_truncate.md) 的 `messages[:index]` 和 `turns[-max_turns:]`。解析 JSON 时剪字符串，仍看 [第 27 课](27_json_parse.md)，这一课不把那一段再讲一遍。

## 先用一句人话

切片交出一份新的列表，里面是原列表中连续的几项。右边那个下标不包含在结果里。负数从末尾往前数。

## 打个比方

一叠纸编号 0、1、2、3。你说「从 1 号拿到 3 号之前」，拿走的是 1 和 2，3 还留在原处。你说「最后两张」，是从倒数第二张一直拿到底。原叠还在，你手里是复印出来的一段。

## 自己动手

```python
papers = ["封面", "第一句", "第二句", "第三句"]
print(papers[1:3])
print(papers[-2:])
print(papers[:1])
print(papers)
```

预期：

```text
['第一句', '第二句']
['第二句', '第三句']
['封面']
['封面', '第一句', '第二句', '第三句']
```

`papers[1:3]` 含下标 1，不含下标 3。`papers[-2:]` 省略右边，表示一直到最后。`papers[:1]` 省略左边，表示从 0 开始，只要下标 1 之前的那一张。最后一行说明原列表没有变短。

空的一段是空列表，不会报错：

```python
print(papers[2:2])
```

预期：

```text
[]
```

字符串也按同一规则切。`订单号` 占三个字：

```python
text = "订单号10086"
print(text[3:])
```

预期：

```text
10086
```

## 常见错误

把右边的下标也算进去。`papers[1:3]` 不是三张，是两张。窗口若把结束下标写成包含，会多留一轮，或者把不该留的 system 切掉。

写成 `papers[-2:0]`。从倒数第二张走到下标 0，方向是往前，切片不会倒着走，结果是空列表。要最近几张，右边留空：`papers[-2:]`。

以为切片会改原列表。`short = papers[-2:]` 之后再 `short.append("新的")`，`papers` 的长度不变。阶段 3 的窗口要这个性质：调用方手里的旧历史还在，交回去的是另一份。

## 练习

1. `papers[-1:]` 得到什么？
2. 为什么截断时用 `messages[:index]` 留开头的 system，又用 `turns[-1:]` 留最近一轮？
3. 七条消息上写 `messages[1:3]`，下标 3 在不在结果里？

## 答案

1. 只含最后一项的新列表，这里是 `['第三句']`。
2. 前一种从 0 取到 system 结束的位置，岗位说明留在最前。后一种从末尾取一轮，旧对话被丢掉。两份都是新列表。
3. 不在。切片的右端不包含。结果是下标 1 和下标 2。
