# time：用秒数计时

[日期时间](36_datetime.md) 把「现在」写成 `2026-04-01 15:04:05` 这种给人看的文本。工单上的创建时间用那个。阶段 3 要回答的是另一件事：这把键还有多少秒过期。那是一个数字，不是日历。

阶段 3 用在内存替身的过期计算，见 [Redis 入门](../stage3_memory/docs/04_redis.md) 和 [离线演示](../stage3_memory/docs/07_offline.md)。真正的 Redis 在服务端倒计时，不调用这个模块。替身没有服务端，只能自己减。

## 先用一句人话

`time.time()` 交回一个浮点数，表示从 1970-01-01 00:00:00 UTC 到现在过了多少秒。`time.sleep(秒)` 让这个进程停住，到点再继续。两个 `time.time()` 相减，就是中间过了多少秒。

## 打个比方

`datetime` 是墙上的日历钟，你把它抄进工单。`time.time()` 是秒表上的累计秒数。TTL 不关心「今天下午三点」，只关心「从现在起再过 1800 秒」。秒表上的两个读数相减，就知道已经过去多久。

## 自己动手

```python
import time

start = time.time()
time.sleep(1)
passed = time.time() - start
print(passed >= 1)
print(round(passed))
```

预期：

```text
True
1
```

`passed` 可能是 `1.001` 这种略大于 1 的数。`round` 之后是 `1`。不要要求小数点后每一位和教程相同。`sleep(1)` 至少停 1 秒，也可能略久一点。

过期可以写成「到期的那一秒」：

```python
import time

deadline = time.time() + 2
print(time.time() >= deadline)
time.sleep(2)
print(time.time() >= deadline)
```

预期：

```text
False
True
```

第一行还没到。停 2 秒之后，现在的读数不小于 `deadline`。阶段 3 的内存实现用这个比较决定 `get` 该交回值，还是把键丢掉。

`sleep` 会卡住整个进程。命令行客服不能为了演示 TTL 停 30 分钟。示例把等待放在离线演示里，并且只等一两秒。

## 常见错误

用 `datetime.now()` 的文本做减法。`"15:04:05"` 是字符串，减不了秒。要算时间差，用 `time.time()` 这种数字，或者用 `datetime` 对象相减。TTL 这里用数字就够。

把 `sleep` 写进顾客每说一句话都要走的路径。客服会在每次回复前卡住。续期应该是立刻把到期时间改到「现在加 1800 秒」，而不是睡到过期再醒。

以为 `time.time()` 在每台电脑上都是本地时钟的字符串。它是 UTC 起算的秒数。两台时钟不准的电脑，秒数会对不上。本阶段的过期只在同一进程里和自己比较，不把这个秒数发给顾客。

## 练习

1. `time.sleep(1)` 期间，后面的 `print` 会先执行吗？
2. `deadline = time.time() + 1800` 表示什么？
3. 为什么工单时间仍用第 36 课的 `strftime`，TTL 却用这一课？

## 答案

1. 不会。`sleep` 停住的是这个进程，到点才执行下一行。
2. 从这一瞬间起，大约 1800 秒之后的那个秒数。1800 秒是 30 分钟。
3. 工单要给人看年月日。TTL 只比较「到了没有」，数字相减就够，不必格式化成文本。
