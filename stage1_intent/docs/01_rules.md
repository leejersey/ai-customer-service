# 顺着规则分类逐行读

先运行，不需要密钥：

```bash
python stage1_intent/01_rule_classifier.py
```

这一课有两个文件。Python 先加载 `rule_intent.py`（因为演示脚本 import 了它），再执行 `01_rule_classifier.py`。两个都要按行读。阶段 0 学过的语法只给链接。

## `rule_intent.py` 第 1 到 8 行

文档字符串说明：这个文件不联网。第 8 行 `import re` 是标准库。

先停下来读 [正则](../../stage0_basics/python_basics/25_regex.md)。`re` 不是 pip 装的。

## 第 10 到 21 行：意图名单和按顺序检查的词

```python
INTENTS = ("咨询", "查订单", "退款", "投诉", "转人工", "其他")
RULES = [
    ("转人工", ("人工", "真人", "客服电话")),
    ...
]
```

元组在 [列表课](../../stage0_basics/python_basics/13_lists_dicts.md) 里讲过。这里用元组，是因为这六个名字不打算在运行中增删。后面的文件都 `import INTENTS`，避免一个文件写「退货」、另一个写「退款」。

`RULES` 是列表，顺序就是优先级。注释说明为什么不用字典：读代码的人从上往下看，先碰到的规则先赢。`转人工` 在 `退款` 前面，所以「转人工，我要退款」会判成转人工。把 `投诉` 挪到最后，同一句话的结果会变。这不是模型「更理解了」，只是你改了检查顺序。

`in` 用来判断词是否出现。复习列表课里 `"quit" in "我想 quit"` 那一题：这是子串，不是整句相等。

## 第 24 到 38 行：抽出订单号

```python
_ORDER_WITH_LABEL = re.compile(r"(?:订单号|订单|单号)\s*[:：]?\s*(\d{4,})")
_LONG_NUMBER = re.compile(r"\d{5,}")
```

名字以下划线开头，表示「本文件内部用」。两套模式是因为顾客有两种说法：带「订单号」标签，或者只丢一串较长的数字。带标签时至少 4 位；没有标签时至少 5 位，避免把「2 天」里的 2 当成订单。

`extract_order_id` 先搜带标签的。找到就 `group(1)`，只要括号里的数字。找不到再搜长数字，用 `group(0)`，因为这个模式没有另加括号。都没有就 `return None`。不要编一个订单号。`None` 课在阶段 0。

删掉第一个模式，「订单号：10086」仍可能被第二个模式接住，因为 10086 有 5 位。删掉第二个模式，「我的单子 20001888 到了没」这种没写「订单」二字的就抽不出来。两个都有，覆盖的形状不一样。

## 第 41 到 60 行：交回一个字典

先停下来读 [函数交回字典](../../stage0_basics/python_basics/24_return_dict.md)。

`slots` 先做好，命中哪条规则都带着同一个订单号。循环是两层：外层每个意图，内层每个关键词。`if keyword in text` 成立就立刻 `return`。后面的规则不再看。所以「我不想退款，只问保修」在碰到「退款」时已经返回，不会走到后面的「保修」。

一个关键词都没有，才落到最后的「其他」，置信度 0.2。0.6 和 0.2 不是模型算出来的概率，是我们写死的「匹配到了」和「兜底」两个档。改它们不会让规则变聪明，只会改打印出来的数字。

`source` 固定为 `"rules"`。后面和模型结果放在一起时，靠这个键知道是谁判的。

## `01_rule_classifier.py`

第 11 行 `from rule_intent import classify_by_rules`。两个文件在同一文件夹，不需要改 `sys.path`。这和阶段 0 的 `import config` 一样。

`SAMPLES` 是演示用的句子，不是标准答案文件。标准答案在第 4 个脚本。这里的句子是为了让你亲眼看见四种现象：

- 「转人工」「订单号：10086」「我要退货」「怎么连接」能对上。
- 「音质好不好」对不上，变成其他。
- 「不想退款」被子串误伤。
- 「怎么样」里含有「怎么」，天气被判成咨询。
- 「你好呀」才是真正落到其他。

`for text in SAMPLES` 复习 [for](../../stage0_basics/python_basics/14_for.md)。打印用 f-string。订单号是 `None` 时，屏幕上就是 `None`，不是空着。那表示没抽到，不是抽到了字面量 None 这四个字母。

文件末尾没有包一层 `try`。规则函数不联网，失败只可能是我们自己写错，应该让追溯露出来。

## 改一行会看见什么

1. 把 `RULES` 里「咨询」挪到最前面，再运行「我不想退款，只问保修多久」。如果「保修」先被看见，意图会变成咨询。看完改回原来的顺序。这证明顺序是设计，不是细节。
2. 把 `_LONG_NUMBER` 改成 `r"\d+"`，用一句「用了 2 天」调用 `extract_order_id`。你应能抽到 `2`。这就是至少 5 位的原因。看完改回 `\d{5,}`。
