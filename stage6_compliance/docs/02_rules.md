## 为什么用短语，并且分输入和输出

辱骂和竞品诋毁，顾客说出来或客服说出来都不该继续。绝对化承诺是客服的回复问题。顾客问「你们保证100%吗」，不是客服在承诺。所以这条的 `where` 只有 `output`。

`sensitive_hits` 先看 `where` 里有没有这次的位置，再看短语是不是出现在句子里。空字符串会命中每一句，所以 `word` 为空就跳过。👉 不懂这里的 `any`？先看 [基础课 · any 和 all](../../00_python_basics/59_any_all.md)。`has_word` 用它演示「过宽的单个字」和「正式短语」的差别，正式收集命中仍是 `for`，这样每一条命中都能留下。

`decide` 把命中收成等级和动作。这一课先看见结论。等级谁覆盖谁，在第 7 课。

## 屏幕上要看的几句

「你们这些垃圾客服」在输入上是高 / 转人工，命中「辱骂:垃圾客服」。

「别家都是骗子，买我们的」在输出上是高 / 拦截。

「我们保证100%不会出问题」在输出上是中 / 改写。同一类说法放在输入「你们保证100%吗」上是低 / 放行，因为这条不查输入。

「未拆封可以七天无理由退货吗」没有命中。

漏报：「废 物」中间有空格，对不上「废物」。人换一种骂法也会漏。规则挡不住所有骂法。

「这款耳机永不关机吗」对不上「永不出现」。如果把词改成单个「永不」，这句会被误伤，所以表里不写单个「永不」。

误报演示不改文件。内存里的 `["垃圾"]` 会命中「垃圾分类怎么预约」。正式短语「垃圾客服」不会。`has_word` 两次的结果是 `True` 然后 `False`。

## 常见坑

- 为了少漏报，把词改成单个字。误报会先于漏报变得无法使用。
- 绝对化承诺也去查输入。顾客的提问会被转人工。
- 词表 JSON 写坏了仍继续跑。`load_rules` 会说明并退出。空词表若被当成「没有规则」，所有句子都会放行，所以缺了 `sensitive` 不能悄悄继续。
- 命中了就以为顾客一定违规。短语对上了，只说明要按表里的动作处理，人仍可能是在引用或开玩笑。这一课先把误报说清楚。

## 练习

1. 把 `rules.json` 里「垃圾客服」临时改成「垃圾」，再运行。哪一句会从放行变成命中？看完改回去。
2. 「保证100%」为什么不放在 `where` 的 input 里？
3. 「废 物」放行，叫做误报还是漏报？

## 答案

1. 「垃圾分类怎么预约」若被你加进脚本，或者任何含「垃圾」的句子，都会命中。示例脚本里的正式结论不应改变；变的是你自己改过的文件。改回去再运行，辱骂仍只命中「垃圾客服」。
2. 那是顾客在问，不是客服在答应。查输入会把正常提问拦掉。
3. 漏报。词在表里，句子的意思也接近，但空格让短语对不上。误报是不该拦的被拦了，例如单个「垃圾」对上「垃圾分类」。
