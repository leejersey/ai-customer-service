# 注释：写给人看、Python 当没看见的字

`01_hello_llm.py` 第 1 行就是：

```python
# -*- coding: utf-8 -*-
```

井号 `#` 后面直到行尾，都是注释。Python 跳过它们，不执行。

## 先用一句人话

注释是便签。厨师做菜时不把便签吃下去。便签用来告诉下一班的人：为什么要这样放盐。

我们仓库里的注释只写「为什么」。某一行在语法上是什么意思，写在代码导读里，不写进注释。否则注释会把每一行再翻译一遍，你反而看不到设计原因。

## 打个比方

菜谱正文是「加 3 克盐」。旁边铅笔字是「上次客人说太咸，不要改回 5 克」。铅笔字不是做菜步骤。

## 文件开头那一行特殊在哪

`# -*- coding: utf-8 -*-` 仍然是注释，Python 不把它当计算。它是给某些编辑器看的标记：这个文件里的中文按 UTF-8 保存。Python 3 默认就用 UTF-8 读源码，所以删掉它，脚本通常照样能跑。留下它，是避免旧编辑器用错编码，把中文注释存成乱码。

你现在不需要背这行的格式。只要认出：它以 `#` 开头，所以不是命令。

## 三引号那一段也不是命令

紧接着文件里有：

```python
"""阶段 0 · 示例 1：一次请求，一次回复。
...
"""
```

这叫文档字符串，英文里常叫 docstring。它是一段用三引号包住的文字，给读代码的人看这个文件是干什么的。放在文件最上面、又没有赋给任何一个名字时，运行脚本不会把它打印出来，也不会因此去调用模型。

三引号本身是字符串的一种写法，细节在[字符串课](07_strings.md)。现在只要知道：文件头上这一大段不是一步步要执行的操作。

## 自己动手

```python
print("会执行")
# print("这行被注释掉了，不会执行")
print("也会执行")
```

预期：

```text
会执行
也会执行
```

中间那行 `print` 因为前面有 `#`，整行被跳过。

注释可以从一行的中间开始，但只覆盖它后面的部分：

```python
print("前半")  # 这是给人看的
```

预期：

```text
前半
```

## 常见错误

以为注释会显示在屏幕上：

```python
# 你好
```

运行后什么都没有。注释不会被 `print`。想显示，就写 `print("你好")`。

用中文全角的井号 `＃`：

```text
SyntaxError: invalid character '＃' (U+FF03)
```

必须是键盘上的半角 `#`。中文输入法打开时很容易打成全角。

把真正要执行的代码留在 `#` 后面，然后奇怪它为什么没发生。那不是程序坏了，是你让 Python 跳过了它。

## 练习

1. 下面两行运行后，屏幕上有什么？

   ```python
   # print("星河")
   print("数码")
   ```

2. 想暂时不发送请求、又不删掉那一行代码，应该怎么做？
3. 我们为什么不在每一行代码上方写「这行是打印」这种注释？

## 答案

1. 只有一行 `数码`。第一行被跳过。
2. 在那一行的最前面加 `#`，需要时再删掉 `#`。这就是「注释掉」。
3. 这种注释只是把代码又说了一遍，没有增加「为什么」。本仓库把「这一行是什么」放在导读里，注释留下给设计原因，比如「失败时不要把半句话留在历史里」。
