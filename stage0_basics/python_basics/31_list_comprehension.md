# 列表推导：用一行做出一张新列表

你已经会写：

```python
gold = []
for item in rows:
    gold.append(item["intent"])
```

列表推导是同一件事的紧凑写法。第一次出现在 `04_evaluate.py` 里取出全部标准答案和规则预测。

## 打个比方

传送带：旧列表的每一件从左边进去，加工一下，从右边出来落进一只新盒子。旧列表不被修改。

## 自己动手

```python
rows = [{"intent": "咨询"}, {"intent": "退款"}]
gold = [item["intent"] for item in rows]
print(gold)
```

预期：

```text
['咨询', '退款']
```

方括号仍然表示列表。里面读成：对 `rows` 里的每个 `item`，把 `item["intent"]` 放进新列表。

带判断时，`if` 写在后面，只留下符合的：

```python
nums = [1, 2, 3, 4]
print([n for n in nums if n > 2])
```

预期：

```text
[3, 4]
```

字典的 `.items()` 一次给出键和值，也可以放进推导：

```python
row = {"咨询": 3, "其他": 2}
parts = [f"{guess} {count} 次" for guess, count in row.items()]
print(parts)
```

预期：

```text
['咨询 3 次', '其他 2 次']
```

评估脚本用它把混淆计数拼成一行字。

## 常见错误

把推导写成生成器却当成列表用多次。圆括号 `(` `)` 包住的是生成器，方括号才是立刻做好的列表。阶段 1 用方括号。

在推导里做联网或打印。它会变难读。推导只做「从每条里取一个字段」这种短步骤。分类函数的调用放进推导可以，但失败时的 `try` 不适合塞进一行，所以模型那一段评估仍用普通 `for`。

## 练习

1. 从 `["转人工", "你好"]` 做出每个字符串的长度列表。预期是什么？
2. 推导会不会改掉原来的 `rows`？
3. 为什么模型评估的循环没有写成一条推导？

## 答案

1. `[len(text) for text in ["转人工", "你好"]]`，预期 `[3, 2]`。
2. 不会。它做出新列表。
3. 每一句都可能抛出网络错误，要 `try` 然后继续下一句。这种多步补救用普通循环更清楚。
