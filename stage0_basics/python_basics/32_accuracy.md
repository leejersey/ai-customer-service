# 准确率：猜对的条数除以总条数

分类器不能靠「我觉得还行」。给每一句一个标准答案，再数有多少句和标准答案相同。

准确率 = 猜对的条数 / 全部条数。20 条对了 13 条，就是 `13 / 20 = 0.65`。0.65 不是 65 条，是 65%。打印时用 `f"{score:.2f}"` 保留两位小数。

## 打个比方

20 道判断题，答对 13 道。分数告诉你整体水平。它不告诉你错在哪一题。所以旁边还要一份「标准答案是咨询时，你有几次写成了其他」。这叫混淆计数：行是标准答案，列是你的预测。

## 自己动手

```python
gold = ["咨询", "咨询", "其他"]
predicted = ["咨询", "其他", "其他"]
correct = 0
for index, expected in enumerate(gold):
    if predicted[index] == expected:
        correct = correct + 1
score = correct / len(gold)
print(correct, len(gold))
print(f"{score:.2f}")
```

预期：

```text
2 3
0.67
```

两份列表长度不同时，下标会越界：

```text
IndexError: list index out of range
```

`metrics.py` 在除法之前先检查长度，不对就 `ValueError`，比算到一半才 `IndexError` 清楚。

混淆计数是字典套字典。外层键是标准答案，内层键是预测：

```python
counts = {}
expected = "咨询"
guess = "其他"
if expected not in counts:
    counts[expected] = {}
counts[expected][guess] = counts[expected].get(guess, 0) + 1
print(counts)
```

预期：

```text
{'咨询': {'其他': 1}}
```

`.get(guess, 0)` 和读环境变量时的 `.get` 一样：没有这个键就用 0，再加 1。

## 准确率不会告诉你的事

- 它不表示模型查过订单。阶段 1 只比较意图标签。
- 全部判成「其他」也可能有一点准确率，因为测试集里真有「其他」。所以还要看混淆，确认不是全都堆在一个意图上。
- 规则准确率低于 1，是测试集故意放了词表覆盖不到的句子。全对的测试集学不到局限。

## 常见错误

用整数除法的旧印象以为 `13 / 20` 是 `0`。Python 3 里 `/` 得到小数。`//` 才是整除。

只报百分比，不报 `13/20`。0.65 看不出一共测了几条。脚本两者都打印。

把「预测对了」定义成字符串里包含标准答案。必须是整个标签相等。`"咨询"` 和 `"其他"` 不能算部分正确。

## 练习

1. 4 条里对了 3 条，准确率的小数是多少？用两位小数写出。
2. 标准答案全是「咨询」，预测全是「咨询」，混淆计数里内层应该是什么样？
3. 为什么规则脚本要断言准确率既大于 0.5 又小于 1？

## 答案

1. `0.75`。`3 / 4` 再格式化成两位小数。
2. `{"咨询": {"咨询": 条数}}`。只有一种预测，而且和标准答案相同。
3. 大于 0.5 说明词表不是瞎猜。小于 1 说明这批句子里仍有规则搞错的，局限还在，值得和模型比较。
