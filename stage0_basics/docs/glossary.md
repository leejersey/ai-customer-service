# 名词表

这一页是词典，不是教程。每个词在对应的课里都有例子和实验。这里只帮你在忘记时快速对上号。

这些解释是为本阶段的客服项目准备的，不是一本完整的计算机词典。

## token

模型用来丈量文本长度的小珠子，不是「一个汉字」或「一个英文单词」的别名。

同一个汉字可能是一颗珠子，也可能被切成多颗。你不用自己切。接口会在 `usage` 里告诉你这次用了多少颗。费用、等待时间和能不能放进一次请求，都按 token 算。

相关：第 1 课看第一份 `usage`；第 2 课看历史变长后 `prompt_tokens` 变大。

## prompt（提示）

这一次请求里你交给模型的全部输入，不只是顾客刚打的那一句。

在本阶段，prompt 通常包括系统提示、已经发生过的用户话、已经发生过的模型回复，再加上最新的问题。`prompt_tokens` 量的就是这一整包，不是单指最新一句。

## system prompt（系统提示）

开发者写给模型的岗位说明，在消息列表里的角色是 `system`。它规定身份、语气和禁止事项。

顾客在终端里通常看不到它，但模型每次都能看到，因为它随请求一起发送，并且占用 token。它不是程序里的硬性检查：写了「不要编造运单号」，模型仍可能编。真正拦截要靠后面阶段的代码。

## context window（上下文窗口）

这个模型这张书桌有多大：一次请求里，提示和回复加起来最多能放多少 token。

超出书桌的内容不会自动被记住或摘要，而是根本放不进这一次请求。所以历史不能无限追加。阶段 0 先看见这个限制，阶段 3、4、5 才处理「放不下以后怎么办」。具体数字以你所用模型的官方说明为准，不要背一个过期的数字。

## temperature（温度）

模型在多个都说得通的下一步用词之间，允许多大的随意性。

接近 0 时更稳，同一句问两遍更像。升高以后用词更散，也更容易跑题。它不表示更聪明，也不保证温度是 0 时两次输出逐字相同。有的模型会忽略这个参数。

## stateless API（无状态接口）

一次请求结束后，服务器不保留你的对话文件夹。下一次请求是新的客人。

模型能「接着上次说」，只是因为我们的程序把旧消息又放进了新请求。这叫无状态。聊天记录存在你的 `messages` 列表里，不存在 DeepSeek 替你开的长期会话里。

## streaming（流式输出）和 SSE

流式输出：模型每写出一小段就送出来，不用等全文写完。总生成时间差不多，但人可以更早开始读。

SSE（Server-Sent Events）是这种「一条连接上连续推很多小消息」的常见传输格式。线上经常能看到以 `data: ` 开头的一行行文本，最后有一行 `data: [DONE]`。OpenAI SDK 会把这些行解析成 Python 对象，所以 `for chunk in stream` 里的 `chunk` 已经不是原始文本行。

每一小段叫增量（delta），是新增加的几个字，不是到目前为止的全文。完整回复要由我们自己拼。
