先运行：

```bash
python stage2_tools_tickets/02_ticket_states.py
```

第一行应是：

```text
合法方向：待处理 → 处理中 → 已解决 → 已关闭
```

前三次箭头打印「允许」。从「待处理」直接到「已解决」或「已关闭」会拒绝，并写明下一步只能是「处理中」。从「已解决」退回「处理中」会拒绝。已经「已关闭」再改，会说这是最后一步。「已发货」会说不认识。这个脚本不产生数据库文件。

```mermaid
flowchart LR
    pending[待处理] --> doing[处理中]
    doing --> solved[已解决]
    solved --> closed[已关闭]
```

订单上的「已发货」「已签收」「待发货」不在这张图里。那是物流。工单只走上面这四格。

## `states.py` 第 8 到 25 行：名单和字典

👉 不懂自己写的类？先看 [基础课 · 类和方法](../../00_python_basics/33_class_methods.md)。

`STATUS_NAMES` 是四个合法名字。多一个空格也算不认识，因为后面是整段字符串相等，不是「里面含有这几个字」。

`StatusMachine` 把规则放进 `self.allowed`。键是当前状态，值是唯一允许的下一步。已关闭没有下一格，所以字典里不写它。不写这个键，`dict.get` 得到 `None`，表示走不下去。

这里不用一长串 `if current == "待处理"`。改流程时改表，`move` 的形状可以不动。阶段 1 的 `HANDLERS` 也是字典，那里装的是函数。这张表装的是状态名字。两张表不要合成一张。

状态机不记住「这张工单现在是什么」。`move` 的 `current` 是调用时传进来的。记住是数据库那一行的 `status` 列，下一课的 `UPDATE` 才会写。

## 第 27 到 39 行：把链打印出来

`chain_text` 从「待处理」出发，顺着 `self.allowed` 走。循环上限是名字的个数。表若被改成一个圈，例如「处理中」又指回「待处理」，这里会停，演示脚本不会自己死循环。这是打印用的保护。业务上的拒绝仍由 `move` 抛出。

箭头字符串是从字典算出来的。你改了表，再运行示例 2，第一行会跟着变。脚本里没有把这行字再写死一遍。

## 第 41 到 54 行：允许就交回，不允许就抛错

先看名字在不在 `STATUS_NAMES`。订单的「已发货」在这一步就被拒绝，到不了后面的「下一步只能是」。

`expected` 是字典里的下一格。已关闭没有这个键，错误句是「已经是最后一步」。有下一格但目标不是它，错误句会把允许的那一格说出来。两种失败的句子不同，你可以从屏幕上看出是「走完了」还是「跳步了」。

成功时 `return target`。函数不修改 `self`。同一台 `StatusMachine` 可以连续判断很多张工单。

## 示例脚本第 12 到 36 行

`CASES` 前三对是合法的一步，后面是跳步、往回、终点、以及物流词。`for` 里用 `try` 接住 `ValueError`。注释写了原因：一个非法例子把进程打死，后面的例子就看不到了。状态机仍然抛错，脚本只是把错印出来再继续。工具函数到下一课才把这种错收成字典。

`continue` 跳过这一轮剩下的打印。允许的那一支才打印「结果是」。

## 常见坑

- 把「已发货」写进工单。`move` 会说不认识。更新工具因此也不会改库。
- 只改 `self.allowed`、不改 `STATUS_NAMES`。新名字在进字典之前就被「不认识」拦住。两个地方要一起改。
- 让状态机自己保存当前状态。两张工单会共用一个「现在」，后一张把前一张盖掉。当前状态必须在每一行自己的列里。

## 改一行会看见什么

1. 把 `self.allowed` 里「待处理」的值改成「已解决」，再运行。第一行的箭头会变，「待处理 → 已解决」会变成允许，「待处理 → 处理中」会变成拒绝。看完改回去。
2. 在 `STATUS_NAMES` 里加一个「已发货」，但字典不加。再运行最后一对。错误会从「不认识」变成「已经是最后一步」或「下一步只能是……」，取决于你有没有给它键。看完把元组改回四个名字。
