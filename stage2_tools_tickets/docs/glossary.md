# 名词表

这一页只收这一阶段新的客服用词。`class`、`with`、SQL、`datetime`、默认参数和星号不在这里，去 [基础课](../../00_python_basics/README.md) 第 33 课往后。阶段 0 已经收过的 token、温度、无状态接口，去 [阶段 0 名词表](../../stage0_basics/docs/glossary.md)。

这一页是词典，不是教程。每个词在对应的脚本导读里都有对着代码的讲解。

## function calling（函数调用 / 工具调用）

一种聊天请求的格式：除了消息，你再给一份工具说明书。模型可以回复普通文本，也可以提出「请执行这个名字，参数是这段 JSON」。

执行发生在你的程序里。模型不打开数据库，也不因为提出了调用就自动有了查询结果。

## tool schema（工具说明书）

`tools` 参数里的一项。它包括函数名、给人读的说明，以及参数的 JSON Schema：有哪些键、什么类型、哪些必填。

说明书不是 Python 函数。两边的名字必须一致，示例 7 会检查这件事。

## tool_calls

助手消息上的一个列表。每一项有 `id`、`type`（这一阶段是 `function`）、函数名，以及 `arguments` 文本。

`finish_reason` 为 `tool_calls` 时，表示模型这一轮停下来是为了等你执行，不是因为话已经说完。

## role=tool

消息列表里的一种角色。`content` 是工具返回值的文本，通常是 JSON。`tool_call_id` 对上某一次 `tool_calls` 的 `id`。

它不是顾客说的，也不是模型写的最终回复。它是程序执行完之后交回去的结果。失败也要有这一条，模型才知道没有查到。

## 槽位

办成这件事之前必须知道的一项事实。这一阶段用到的是订单号。抽不到就是空的，程序追问，不编一个号。

## 追问 / 补槽

顾客说「我要退款」但没有订单号时，先问，并把意图和原话记在 `session["pending"]` 里。下一句补上号码，才调用工具。

问句写在程序里。来源显示为 `slots` 的那一轮，是在完成上一问，不是重新做一次分类。

## 状态机

一张「当前状态只能到哪一格」的表，外加检查这张表的动作。这一阶段的链是：待处理，处理中，已解决，已关闭。

它不负责记住某一张工单现在的状态。那一格在数据库的行里。

## 工单

为了让人稍后处理而插入的一行：谁、哪张订单、类型、描述、状态、创建和更新时间。

退款工单不是退款本身。这一阶段不会打款。投诉可以没有订单号。转人工也写成工单，是为了把「要换人」留在表里，而不是只在回复里说一句。
