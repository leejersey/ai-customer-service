# 名词表

这一页只收这一阶段新的客服用词。切片、注解、dataclass、JSON 来回、连接对象、`time`、环境变量的默认值不在这里，去 [基础课](../../00_python_basics/README.md) 第 39 课往后。阶段 0 已经收过的上下文窗口、token、无状态接口，去 [阶段 0 名词表](../../stage0_basics/docs/glossary.md)。槽位和工单在 [阶段 2 名词表](../../stage2_tools_tickets/docs/glossary.md)。

这一页是词典，不是教程。每个词在对应的脚本导读里都有对着代码的讲解。

## 对话历史

`messages` 列表。每一项是谁说的、说了什么。它回答「刚才说过什么」。

它会变长，也会被窗口或摘要换掉。它不是工单表，也不是 Redis 这个软件本身。

## 工作记忆

这一单办到哪了：意图、槽位、正在等的那一项、手头的工单编号、任务状态。

本阶段用 `WorkingMemory` 这张小表。对话历史可以切短，小表上的订单号还可以留着。它不保存全部闲聊。

## 短期记忆

为了让这一段会话在进程外面再留一会儿而放进 Redis 的那几把键：最近的消息、摘要、工作记忆。

按 `session_id` 分开。空闲超过 TTL 就消失。重启程序，只要 Redis 还在、键还没过期，同一编号能接上。它不是永久档案。

## 长期记忆

可以跨很多天再找回来的顾客偏好。本阶段不做。阶段 5 才会用向量去检索。

把 Redis 的过期时间调得很长，仍是一堆按键存放的原文，不是长期记忆。工单表也不是长期记忆：它是待人处理的业务记录。

## 上下文窗口

这个模型这一次请求能放下的 token 上限。阶段 0 的名词表里已经有这个词。

本阶段用两种办法面对它：截断，把旧内容移出这一次请求；摘要，用更短的文字换掉旧内容。字符数只是课堂上的长度尺，账单仍按 token。

## 截断 / 滑动窗口

只保留开头的 system，再保留最近若干轮，或按字数从最新一轮往前装。

被移出窗口的句子不再出现在下一次请求里。若订单号只写在那些句子里、又没有放进工作记忆，后面就不知道这个号。

## 摘要

用一段较短的说明替换旧消息，最近几轮仍保留原文。

有模型时请 DeepSeek 写。没有密钥、或模型失败时，用每句开头拼成的假摘要。假摘要能让练习跑完，它不理解对话。

## session_id

一次会话的名字。Redis 的键由它和固定前缀拼出来。

`demo-1` 和 `local` 是两段会话。编号相同，才读得到同一份订单号和同一串消息。

## TTL

键还能活多少秒。`-1` 表示没有过期时间，`-2` 表示键已经不在。

本阶段的会话默认 1800 秒，也就是 30 分钟没有访问就过期。每次读写都把秒数拨满，所以顾客还在说话时，倒计时会重新开始。

## Redis

一个单独的进程里的键值存储。Python 用 redis-py 这个客户端连上去。

值可以是字符串、列表或哈希。本阶段用字符串存摘要，用列表存一条条消息 JSON，用哈希存工作记忆的栏目。它和 SQLite 同时存在：一个放会过期的会话，一个放工单账本。
